## 1. 背景

1. **产品背景**：Atlas 四任务信息架构（自由刻度／人生轨迹／风险实验室／原理档案，brief §一）取代九面板平级目录，四页共享公共骨架（原型 §0），并在平板/移动形态引入参数侧栏、折叠承载、时间透镜等新容器需求。
2. **研究背景**：WF-02 组件层对照研究（research-ds-comparison.md）已对 TDesign / Ant 系 / Semi 三家与本仓 Arco 2.66.18 基线完成逐场景实测对照（其 §二 B1–B7 表、§三 令牌架构 C 表），并给出 ADR 草案（其 §四 D 表）。本文不重开论证，只把草案收敛为可执行裁定。
3. **约束背景**：
   - brief §八.1：不新增运行时依赖，迁移仅在 ADR 论证收益后渐进——即本文就是那次论证；
   - 宪法 §5.1（design-language.md:176）：签名元素/令牌层面变更须三步准入；S1–S26 签名元素零回退为红线（design-language.md:188 P7 收口记录）；
   - 尺寸门禁：原始字节硬限（p6 实测 2,001,800 B 超 2,000,000 B 即降档，design-language.md:187），任何跨库引入都直接侵蚀 135 B 量级的余量现状。
4. **三选一口径定义**（每场景必须落其一）：
   - **保留 Arco 现状**：不改组件用法，现有实现直接承载新场景；
   - **Arco 配置启用**：在库组件（`@arco-design/web-react@^2` 已含）经参数/属性配置启用既有能力，零新依赖；
   - **自研抽象**：本仓内少量自建组件/逻辑，挂既有令牌与签名元素语义，仍零新依赖。

## 3. 逐项裁定

### 3.1 D-B1 分步引导 —— 自研抽象

- **场景**：人生轨迹「人生规划分步」引导（自由刻度首引导同构）。
- **裁定**：自研抽象。自研件 = 分段控件 + 进度指示，挂既有令牌与 S1/S2 语义；**不引入任何库的 Steps 组件**。
- **理由**：人生轨迹「分步」实为渐进披露（A4/A7 原则裁定，research-ds-comparison.md §一），不是强制流程；现有 Radio 分段（3 组）+ 组内 Tabs 已承载且带 S20 指示条滑动 / S21 数字键切组（AdvancedPanel.tsx:48-76,150-171，research 实测）；三家 Steps 均为纯导航指示器、不承载内容面板，引入只增导航噪音、不换能力（research §二 B1 结论）。
- **迁移触发条件**：出现真正的**强制流程**（如分享导入向导、多步数据接入）时重评——届时先比较 Arco Steps（在库）与自研，仍不跨库。

### 3.2 D-B2 参数侧栏 —— Arco 配置启用

- **场景**：四任务**移动「底部参数面板」**的潜在实现（原型 §1.2 320–479 档底部 Sheet；§2.2/§3.2 移动列为互斥 Collapse 页内承载，不消费本裁定）。**平板消费位显式注销（评审复核轮修订）**：原型平板列的「按需侧栏 / 浮动检视器」已落为图上方横向分段条（原型 §2.1/§3.1）与 tooltip 类轻量浮层（原型 §1.1），不经侧栏浮层——Drawer 对平板**备而不用**；平板形态若改回侧栏/检视器，须先修订本条。
- **裁定**：Arco 配置启用。移动底部参数 Sheet 以 Drawer `placement="bottom"` 为潜在实现；「非模态检视器」备位＝Drawer `mask={false}` + `placement`/`width`（`interface.d.ts:95-101` mask 默认 true 可关，research 实测）；声明处渲染。实现映射随 WF-03 移动底部 Sheet 施工落位，平板不施工 Drawer。
- **理由**：非模态能力四家齐备（TDesign `showOverlay` / antd `mask` / Semi `mask` 同理可关），Arco 现状库配置即满足；Semi SideSheet 需显式关 body 锁滚（官方注意项），TDesign 需关防滚动穿透——跨库引入反而多坑（research §二 B2 表）；「推开内容」语义仅 TDesign `mode=push` / antd `push` 有，本仓双栏并排（BasicCalculator.tsx:501-508，research 实测）下无刚需。
- **迁移触发条件**：需要「推开内容」动效（TDesign mode=push 独有）或抽屉可拖宽（TDesign sizeDraggable）时重评；重评仍以 Arco 生态内方案优先。

### 3.3 D-B3 折叠承载 —— 保留 Arco 现状

- **场景**：四任务 L3 分析区折叠（敏感性 / 生命周期图 / 对比表等按需披露）与既有核心参数折叠。
- **裁定**：保留 Arco 现状。Tabs `lazyload` 无 `destroyOnHide` + 组间 `hidden` 包裹（AdvancedPanel.tsx:150-171）与核心参数 Collapse 未传销毁属性（BasicCalculator.tsx:1089-1090）——均 research 实测——直接承载，不迁移。
- **理由**：hidden 非卸载已是既定且验收过的形态；Semi Collapsible 默认折叠即销毁 DOM（keepDOM 默认 false）是反向教训，其官方 FAQ 另有父级隐藏测高失败坑（research §二 B3 表）；本仓已运行模拟结果与表单输入天然保留、分享/情景库回填状态不受切换影响（useCalculatorStore.ts:288,297 入链口径，research 实测）。
- **实施约束**（随本裁定生效）：折叠不得销毁 DOM（含表单值 / 滚动 / 焦点状态）。
- **迁移触发条件**：某折叠内容首挂成本被实测证明过高时，用 Arco Tabs 内建 `lazyload`（首展挂载）而非跨库。

### 3.4 D-B4 时间轴 / 锚点 —— 拆分裁定

- **场景 a（原理档案锚点导航）**：**Arco 配置启用**。Arco Anchor 组件包在库在位（node_modules es/Anchor 目录，research 实测）、本仓未用，长文侧导航等价能力无须跨库（research §二 B4 表）。
- **场景 b（人生轨迹时间透镜）**：**自研抽象**。时间透镜是「拖动年龄刻度同步检视」的连续输入控件（原型 §5.1 全规格），Semi Timeline 是只读事件列表且连线与时间点均 `aria-hidden`、节点对读屏不可达——与原型 §四 图表须非视觉替代口径相斥（research §二 B4 表）。
- **迁移触发条件**：时间透镜若改为「事件卡片流」展示形态，重评 Timeline 语义（仍优先 Arco Timeline 同类能力，不跨库）。

### 3.5 D-B5 表单联动 —— 保留 Arco 现状

- **场景**：自由刻度 / 风险实验室的参数联动（目标值与基础模式临界值实时联动、计发月数与退休年龄对照等）。
- **裁定**：保留 Arco 现状。zustand 单 store 显式同步标志 + action 承载（useCalculatorStore.ts:93,98,145，research 实测），不迁移 antd Form `dependencies`。
- **理由**：两者语义不同构——`dependencies` 是单 Form 实例内字段级校验/重渲联动，本仓是跨面板数值同步 + 分享入链可复现（联动态「所见即所得」入分享链）；迁移等于重新发明且丢掉入链一致性（research §二 B5 表）。
- **迁移触发条件**：同面板内字段校验联动密度显著上升时，局部启用 Arco 自身 Form 体系声明式校验（不涉跨库）。

### 3.6 D-B6 工作台 —— 保留 Arco 现状

- **场景**：自由刻度桌面双栏工作台（左 hero 右面板、输出卡紧凑模式、Grid 栅格）。
- **裁定**：保留 Arco 现状。双栏 + Card + Grid 直接承载（BasicCalculator.tsx:483-508,870-874，research 实测）。
- **理由**：ProCard 分栏语义与现双栏等价，仅命名/断点表达参照；StatisticCard 与本仓 Statistic 反采纳先例（countUp 无减弱动效参数，design-language.md:170）+ 数字纪律（S3/S18 已自建且可测）冲突；StepsForm「流程强制 + 末步清态」与「参数改动即时重算、状态全程可逆」（brief §七）语义相斥（research §二 B6 表）。
- **迁移触发条件**：WF-03 后工作台密度不足时，先试 Grid/容器查询，再谈组件层。

### 3.7 D-B7 移动结构 —— 保留 Arco 现状

- **场景**：四任务移动形态（顶导航 + 内容 + 底部主操作 + 参数面板）。
- **裁定**：保留 Arco 现状。既有 `wf-action-dock`（<768 常驻自然可达区，BasicCalculator.tsx:1143-1144，research 实测）直接承载。
- **理由**：dock 已覆盖 antd-mobile NavBar「全局导航 + 底部主操作」语义；「复制分享」为主按钮全宽的跨形态不对称已登记为有意例外（design-language.md:189 §5.6 V6）；TabBar 语义在四任务 IA 下无对应需求（四任务是区域不是平级 Tab 页，research §二 B7 表）。
- **迁移触发条件**：出现平级多任务切换需求（当前四任务 IA 不存在）时重评。

### 3.8 D-C 令牌架构 —— 保留 Arco 现状

- **场景**：全局主题/令牌体系（四任务与既有六面板共用）。
- **裁定**：保留 Arco 现状。静态 CSS 变量 + 三源五点对账（types.ts ThemeTokens + defaults THEME/THEME_DARK + App.tsx 注入 + global.css 双块）不迁移 antd v5 算法化深色。
- **理由**：antd 以 CSS-in-JS 运行时从 Seed Token 派生 Map/Alias Token，与本仓「静态产物 + 字节门禁硬限 + 三源对账」是两套不相容架构；迁移收益（主题自动派生）对「仅两主题、新增令牌频率低」的本仓为负，且引入运行时与 p6 门禁先例直接冲突（research §三 C 表）。令牌演进需求（Atlas DS 提案）本就走宪法 §5.1 增量准入，不依赖派生引擎——见配套 `docs/atlas-tokens-evolution.md`。
- **迁移触发条件**：未来主题数 > 2 或需要运行时主题热切换能力时，重评派生引擎。

## 5. 纪律相容性核查

1. **单运行时**：9 个子裁定全部不新增运行时依赖——「保留现状」零改动；「Arco 配置启用」用 `@arco-design/web-react@^2` 在库组件参数（Drawer/Anchor 均在库）；「自研抽象」为本仓内组件，挂既有令牌。本会话实测 package.json:17-25 运行时依赖 7 件（Arco / i18next / react / react-dom / react-i18next / recharts / zustand），裁定后应保持不变。
2. **宪法衔接**：裁定涉及的签名元素（S1/S2/S20/S21/S18/S25）全部为已落地资产，零回退（S1–S26 零回退红线，design-language.md:188）；本 ADR 不新增签名元素、不改令牌——令牌演进另见 `docs/atlas-tokens-evolution.md` 预审登记。
3. **门禁相容**：自研抽象件（分段控件/时间透镜）在 WF-03 施工时计入尺寸门禁复测；跨库引入路径已全量封死（E1–E11，含组件库整体替换），不存在侵蚀 135 B 余量的组件层方案。
