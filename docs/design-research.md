## ① 业界主流设计规范要点汇总

### 1.1 文本对比度目标

| 场景 | 目标值 | 口径来源 |
| --- | --- | --- |
| 正文级文本（< 18pt/24px，非粗体） | **≥ 4.5:1** | 国际无障碍标准 WCAG 2.2「1.4.3 对比度（最低）」AA 级；两大移动端平台规范同口径（其一明确「自定义前景/背景色对建议向 7:1 努力，小字尤甚」） |
| 大字文本（≥ 18pt 非粗体 / ≥ 14pt 粗体，约 24px / 18.7px） | **≥ 3:1** | 同上（WCAG 1.4.3 大字定义；平台规范的无障碍章节给出同表：≤17pt 4.5:1、18pt 3:1、粗体一律 3:1） |
| 非文本指示（焦点环、选中态描边、控件边界、必需图形） | **≥ 3:1** | WCAG 2.2「1.4.11 非文本对比」AA 级 |
| 占位符 / 禁用文字 | 无强制口径；业界实践普遍低于 AA | 组件库实测：深色占位 = 40% 白叠底合成约 **3.8:1**、浅色占位灰（#C9CDD4）对白仅 **1.59:1**（本会话复算）；承载必要信息的提示文字应按正文口径 4.5:1 从严，纯装饰占位可豁免但须如实登记 |
| 材质上的文字 | 半透明底须按「常态合成底 + 最不利透底」双口径验收 | 本文项目已采用此口径（design-spec 5.3），业界无更细的公开数值 |

### 1.2 深色表面的层级色阶方法

- **深色层级不靠阴影，靠表面明度差**：移动端平台规范明确深色模式用「基础组（base）与抬升组（elevated）」两套背景色——抬升面**更亮**、底面更暗后退，前台界面因此前进；阴影仅作辅助通道。
- 新一代色彩体系用**色调（tone）阶梯**替代旧的「海拔叠加白雾」机制：同一中性色板按明度取不同档位填充不同层级表面，层级间差异控制在「可感知但不喧宾夺主」的低对比区间（页面底 vs 卡片底约 1.1–1.2:1）。
- 组件库实测锚点（本仓库 node_modules 内样式表 540–589 行）：深色底 5 级 `#17171A → #232324 → #2A2A2B → #313132 → #373739`；文字四级 = 白透明度 `90% / 70% / 50% / 30%`；填充四级 = 白透明度 `4% / 8% / 12% / 16%`（悬浮/按压等状态底即在此梯上取档）。
- **深色下避免高饱和色**（组件库官方暗色指引原文口径：高饱和色在暗表面上视觉「抖动」，应改用低饱和或柔和色）；语义色深色版应提亮、微降饱和（本项目深色涨 `#27C346` / 跌 `#F98D86` 即此方向，本会话复算均 ≥ 4.5:1 双口径）。
- 半透明材质的透明度**不是自由参数**：以「最不利透底」（深色取纯白内容滚过卡下）合成后按 1.1 的口径验收。

### 1.3 动效时长与缓动族

- **时长分档**（业界新一代动效体系的完整档位）：小反馈 50/100/150/**200ms**（选择控件 200ms）；中区域过渡 250/300/350/**400ms**；大范围表达性过渡 450/500/550/600ms；环境类过渡 700–1000ms（罕见，非用户输入驱动）。
- **缓动族**（CSS 贝塞尔原文）：
  - 标准：`cubic-bezier(0.2, 0, 0, 1)`（常规过渡默认档）；
  - 标准减速：`cubic-bezier(0, 0, 0, 1)`；标准加速：`cubic-bezier(0.3, 0, 1, 1)`；
  - 强调减速：`cubic-bezier(0.05, 0.7, 0.1, 1)`；强调加速：`cubic-bezier(0.3, 0, 0.8, 0.15)`（仅大范围表达性过渡）。
- **行为准则**（移动端平台规范的动效章节）：动效必须有信息目的；反馈动画「短且精确」优先；高频交互不加动效；动效应可被打断/取消；不依赖动效传达唯一信息；减弱动效偏好下应降级——收紧过冲、跟随手势、以淡变替代位移、**避免模糊进出动画**。
- 透明度过渡不使用过冲曲线（过冲会让淡入出现「回闪」）；数值滚动类动效用渐近族（先快后慢、无过冲）。

### 1.4 模糊材质的强度建议

- **材质「厚度」= 不透明度 = 文字对比度的权衡**：平台规范原文口径——厚材质（更不透明）为精细元素提供更好对比；薄材质（更透）保留背景语境；有大量文字的组件（告警、侧栏、弹层）应使用「常规」变体（模糊 + 亮度调整保证可读性）。
- 高透变体仅用于视觉丰富的媒体背景之上；若底下内容较亮，须叠 **35% 黑色压暗层**保可读性（平台规范给出的唯一具体数值）。
- 平台规范**不公开统一的模糊半径数值**；业界组件库落地实现常见「16–24px 模糊 + 1.4–1.6 倍提饱和」组合，层级靠「模糊半径递进（16/20/24）+ 不透明度递进 + 阴影档」三维度同时拉开。
- 不支持背景滤镜的环境须提供实底回退，且**只允许失去通透感、不允许失去层级语义**（描边 + 阴影仍在）。

### 1.5 触控目标尺寸

| 口径 | 数值 | 来源 |
| --- | --- | --- |
| 移动端平台默认 / 平台最小 | **44×44 pt（默认）/ 28×28 pt（最小）** | 平台规范无障碍章节（按平台分级表） |
| 另一移动平台基准 | **48×48 dp，间距 ≥ 8 dp** | 平台无障碍官方指引 |
| Web（WCAG 2.2） | **24×24 CSS px（AA，2.5.8）**，例外条款：间距足够 / 存在等价控件 / 行内 / UA 默认 / 必要 | WCAG 2.2 Understanding 原文 |
| 控件间距 | 带边框元件周边约 **12 pt**、无边框约 **24 pt** | 平台规范无障碍章节 |

结论口径：Web 项目以 44px 为「主流移动平台同级基准」，24px 为「底线」，48px 为「更保守上限」；44px 命中区 + 命中区扩展层（padding 扩大、负 margin 抵消布局位移）是普遍合规做法。

### 1.6 表单与列表密度

- 间距以 **8pt 基线网格**组织（基准档 8，倍数 2/4/6/8 … 48/56/64/72）；组件内**优先用 padding 与 gap，慎用 margin**（margin 因子元素而异、不成体系——新一代间距规范原文口径）。
- 表格密度业界普遍四档（组件库 API 实测：默认 / 中 / 小 / 迷你），行高档位差约 8px；列表/表单密集档用于数据工具类界面。
- 密集表单惯例：标签与控件行距 **4px 级**、字段与字段间距 **8–12px**（本项目现状 4px / 10px 落在此带内）。
- 搜索/输入类容器参考值：垂直内边距 8dp、元素间水平 gap 8dp、距屏幕边缘 24dp（聚焦时 12dp）。

### 1.7 空态与加载态

- **空态**：绝不留无提示空白；组件级空态元素（如表格的空态插槽/配置项，组件库 API 实测 `noDataElement` / 空态组件「图标 + 描述 + 行动入口」结构）；空态文案与正文同级可读（即 1.1 口径）。
- **加载**：
  - 极短等待（防抖级、<300ms）直接出结果，不出现加载态；
  - 触发式动作在按钮内嵌 loading 态并禁用防重复提交；
  - 长任务给进度反馈（进度条 + 阶段文字）；
  - 骨架屏适用于「内容结构稳定、等待 > 1s」的页面级加载；低延迟计算场景用骨架屏会造成闪烁，业界通行做法是小型旋转器 + 文字说明。
- 加载/空态文案必须走多语言资源（不得硬编码单语字符串）。

### 1.8 图表可读性与色盲安全

- **信息不得仅靠颜色**（WCAG 1.4.1，Level A）；红绿色觉障碍在男性中比例约 4–8%（公开色彩通用设计资料口径），「红绿对」与「深底纯红」均为明确反例。
- **冗余编码**：同时使用线型（实线/虚线）、粗细、形状、直接标注（图上直接标而非远距离图例匹配——色彩通用设计原文建议）；本项目两图以线型分层落实：蒙特卡洛图为 50 条抽样路径（装饰层，`strokeOpacity 0.12`）+ 中位数实线（信息层，2.5px 粗）两级；目标虚线（6 4 dash）由打工模拟（积累路径）图承载。
- **色盲安全替代板**（公开的无歧义色板）：蓝 `#0072B2`、橙 `#E69F00`、天蓝 `#56B4E9`、蓝绿 `#009E73` 等；蓝/橙对是「涨/跌」双分类的最常用替代（本项目浅色档 `#0072B2 / #E69F00`、深色档 `#56B4E9 / #E69F00` 与之一致）。
- **分层对比度口径**：装饰层（网格线、抽样路径）低对比可接受（本项目深色网格 `#3D3F46` 对卡底 1.49:1、浅色约 1.2:1，业界网格线普遍同带）；**信息层**（中位数线、目标线、刻度文字）须达标——非文本 ≥3:1、文字 ≥4.5:1；刻度文字 ≥12px；网格用虚线降低视觉权重（本项目 `3 3` dash 已符合）。

### 1.9 数字格式化

- **千分位分组 + 列内固定精度**：同一表格列内 minimum = maximum 小数位，避免 `3,250` 与 `991,128.1` 并列参差（本项目 `formatMoneyFixed` 已实现此口径）。
- **等宽数字**：`font-variant-numeric: tabular-nums`（OpenType `tnum`）用于表格数值列、并排金额、动态数字，防止位数变化时抖动；可叠加 `lining-nums` / `slashed-zero`。
- **跟随界面语言的 locale**：数字与时间格式化应使用当前 UI 语言对应的 locale（标准国际化 API），而非硬编码单一 locale——否则英文界面出现中文习惯的时间串。
- **非有限值统一占位**（如 `—`）、币种符号前置 + 未知代码兜底、大数换算（元→万）遵循本地习惯并保留原值可复算。

## ③ 明确不采纳项及理由

| # | 业界做法 | 不采纳理由 |
| --- | --- | --- |
| N1 | 强调缓动族双段贝塞尔（`cubic-bezier(0.05,0.7,0.1,1)` / `cubic-bezier(0.3,0,0.8,0.15)`）与 250–600ms 大范围过渡档 | 本项目设计原则 1（克制：同屏 ≤2 动效、入场只在首次播放）；现有 360ms 慢档仅授予两个信息承载动效，引入强调族会扩大动效面且图表库动画仅支持预设曲线（design-spec 8 的既有结论） |
| N2 | 三级对比度切换（standard / medium / high 令牌组） | 需 26+ 色彩角色全量令牌与用户设置面板，远超本项目体量；现行「深色全组 ≥4.5 双口径」已高于 standard 档的最低要求，收益为负 |
| N3 | 触控目标上调至 48px 基准 | 两大移动平台口径并存（44pt 与 48dp），Web 侧 AA 底线仅 24px；本项目 375px 窄屏布局密度受限，44px + 命中区扩展已满足全部口径；上调将挤压单行工具组（`global.css:531-538` 现状注释的换行预算） |
| N4 | 深色文字/占位采用纯透明度梯（白 90/60/40/26%） | 40% 档合成后 ≈3.84:1、26% 禁用档更低，低于本仓 4.5 口径；本仓用实测实色（深色次级 `#A9AEB8` 7.05:1）更严。业界梯子可作参考系但不作为验收口径 |
| N5 | 骨架屏加载态 | 面板结果为防抖即时输出（毫秒级），骨架屏必然闪烁；业界骨架屏适用前提是「结构稳定 + 等待 > 1s」，不满足 |
| N6 | 空态插画体系（插画 + 标题 + 描述 + 行动按钮的完整空态组件） | 计算工具无大数据列表空态场景；Alert 文案已承载信息；插画资源与 2MB 尺寸门禁（`npm run check:size`）冲突 |
| N7 | 高透材质变体 + 35% 黑压暗层（媒体沉浸场景方案） | 本项目无媒体背景场景；文字承载面按「厚材质」口径（0.72–0.95 不透明度 + 最不利透底验收）已覆盖该数值所解决的问题 |
| N8 | 旧代深色「海拔白雾叠加」机制 / 新代五级 surface-container 角色组 | 前者已被业界替代且本仓从未使用；后者需要中性色板 tone 生成算法，本仓 3 级材质 + 实底卡（页 1.14:1 层叠差）+ 阴影双通道已达成同等层级语义 |
| N9 | 色盲安全全色板（8 色分类板） | 本项目分类维度只有涨/跌二元 + 单主色，蓝/橙对已覆盖；引入全板徒增令牌面 |
| N10 | `slashed-zero` 等宽数字叠加特性 | 默认字体栈（system-ui / 中文系统字体）对 `zero` OpenType 特性支持不稳定，收益趋零；仅采纳 `tabular-nums`（A4） |
