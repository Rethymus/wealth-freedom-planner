# 高级面板导航模式专项研究（research-advanced-nav）

> 版本：v1.0（2026-11-20）
> 范围：`src/components/AdvancedPanel.tsx` 九个子面板（反向估算 / 贷款 / 收租 / 蒙特卡洛 / 税务多币种 / 打工 / 养老金 / 情景对比 / 公式原理）的导航组织方式重构——组件选型对比、断点形态、面板标题文案规范、迁移清单。
> 核心立场：**导航组件先定「语义」再定「形态」**——九个子面板是互相平行的工具（无先后依赖），凡语义暗含「序列」或要求「内容必须已在页面上展开」的组件都应排除；形态（竖排分栏 / 横滚页签 / 竖排堆叠）随后在既有五档断点矩阵上逐档裁定。用户反馈「有且仅能开启一项」与互斥折叠面板的业界定义完全同构，是改动面最小、语义最贴合的主方案。
> 门禁声明：外部来源一律以中性来源标签标注（源 A–F），表述为「业界主流设计体系 / 业界无障碍规范 / 业界可用性研究机构」；不出现平台 / 公司 / 产品 / 人名品牌字样；npm 包名、组件属性名、源码文件路径等实现层标识符属豁免口径，仅以代码标识符形式出现。原始 URL 因门禁「全程中性表达」未收录，来源对应关系见 §10，抓取时间 2026-11-20。
> 本会话已执行的核查：组件库源码逐文件核查（源 B，四个组件目录 grep / 通读，锁定版本 2.66.18）、官方文档仓组件说明全文抓取（源 A 四篇）、业界无障碍模式指南两页全文抓取（源 C）、同类通用组件库「何时使用」指引四页全文抓取（源 E）、可用性研究机构两篇全文抓取（源 F）、本仓业务代码与既有研究文档盘点（源 D）。**未核验**：某移动端生态设计体系的组件指引页（该站点需脚本渲染，正文不可得，本文不引用其任何内容，如实登记于 §9）。**未执行**：浏览器实测走查（列为 §7 验证方法，落地时执行）。

## 0. 摘要

1. **语义裁定先行**：四个候选组件的官方定义双源对照（源 A × 源 E，§2）后——步骤条被排除（两源均定义为「按流程完成任务 / 存在先后关系」，九面板是平级工具）；锚点被排除为主方案（两源均定义为「跳转到页面指定位置」，前提是内容已在页面上，不解决页长问题，且其默认改写 URL hash 的行为与本仓分享链接 `#s=` 前缀冲突，share.ts:39）；标签页与折叠面板语义均成立，胜负手在键盘实证与迁移成本（§3、§5）。
2. **键盘实证（决定性差异）**：本仓锁定版本 2.66.18 的标签页**没有方向键导航**——页签仅有 Enter 触发（源 B `es/Tabs/tab-header/tab-title.js:42-47`），且全部页签 `tabIndex: 0`（无游移焦点模式），九个页签 = 九个 Tab 停留点，偏离业界无障碍模式指南的方向键 + 单停留点规范（源 C 选项卡模式）；折叠面板头已具备 `role="button"` + `aria-expanded` + Enter（源 B `es/Collapse/item.js:57-63`），互斥改造**不引入任何键盘语义变化**。
3. **互斥语义有业界背书**：业界无障碍模式指南的手风琴模式明文支持「同一时间仅一项展开」的实现（源 C：「If the implementation allows only one panel to be expanded … collapses that panel」）；同类通用组件库设计规范将「手风琴」官方定义为「只允许单个内容区域展开的特殊折叠面板」（源 E）。本应用所用组件库的 `accordion` 属性在源码层的互斥逻辑为 `newActiveKeys = [key]`（源 B `es/Collapse/collapse.js:94-95`）。
4. **推荐方案**：主 = **互斥 Collapse（`accordion`）+ 标题两行文案（短标签主行 + 描述副行）**，其余三项作为补充 / 存档（§6）：标签页竖排只作未来桌面增强存档（键盘缺口需自补方向键）；深链直达（受控 `activeKey`）登记为候选；锚点、步骤条不采纳。信息架构分层指导（源 F「分块」）评估后**不引入分组标题**——避免踩中「披露层级超过两层可用性差」的明确警告（§4.3、§8）。
5. **适配度评分**（§5，7 维 × 5 分制）：互斥 Collapse 32/35 居首；标签页竖排 26/35（键盘与移动形态拖累）；锚点 17/35、步骤条 16/35（语义不成立）；现状平铺 18/35（单屏焦点 1 分即用户主诉）。
6. **迁移清单**（§7）：涉及 3 个文件（`AdvancedPanel.tsx` 一行属性 + 三份 i18n 文案 + global.css 一段副行样式）；aria 与键盘语义**零变化**（逐条比对表见 §7.2）；回归风险集中在「多面板同屏对照能力丧失」的产品取舍与三语文案同步，均给出缓解与验证方法。
7. **顺带消解一项无障碍隐患**：业界规范警告「约 6 个以上可同时展开的面板不宜使用 region 地标」（源 C 手风琴模式）；现状九面板可同时展开恰在该警告区间，互斥改造后同开面板数恒 ≤1，隐患自动消解（§3.2）。

## 2. 主题一：候选组件的官方语义与适用条件（双源对照）

两套来源独立成文：源 A = 本应用所用组件库官方文档仓的组件说明；源 E = 同类通用组件库设计规范的「何时使用」指引。两源互不引用而结论一致，构成交叉印证。

| 组件 | 源 A 官方定义（组件说明首句） | 源 E「何时使用」 | 适用条件提炼 |
| --- | --- | --- | --- |
| Tabs 标签页 | 「将内容组织同一视图中，一次可查看一个视图内容」 | 「提供平级的区域将大块内容进行收纳和展现，保持界面整洁」 | **平级**内容收纳；同屏只看一个；适合九面板 ✓ |
| Collapse 折叠面板 | 「可以折叠 / 展开的内容区域」 | 「对复杂区域进行分组和隐藏，保持页面的整洁。**手风琴**是一种特殊的折叠面板，只允许单个内容区域展开」 | 长内容收纳；互斥（手风琴）是官方命名变体 ✓ |
| Anchor 锚点 | 「通过锚点可快速找到信息内容在**当前页面**的位置」 | 「需要展现当前页面上可供跳转的锚点链接，以及快速在锚点之间跳转」 | 前提 = 内容**已在页面上**（通常全部展开）；只解决「找位置」，不解决「页太长」 ✗ |
| Steps 步骤条 | 「明示任务流程和当前完成程度，引导用户**按照步骤**完成任务」 | 「当任务复杂或者**存在先后关系**时，将其分解成一系列步骤」 | 序列语义；九面板为平级工具，语义不符 ✗ |

- 标签页的位置变体：`tabPosition: 'left' | 'right' | 'top' | 'bottom'`（默认 `top`，源 A API 表；类型声明同项见本仓 `es/Tabs/interface.d.ts`）；源码层 `left`/`right` 即竖排方向（`direction: 'vertical'`，源 B `es/Tabs/tabs.js:95-100`）。
- 标签页的溢出形态：`overflow: 'scroll' | 'dropdown'`（默认 `scroll`，源 A）——页签过多时横滚或收进下拉；九个短标签在 375px 视口横滚需滑动寻址（§3.1 键盘 / §5 移动形态项）。
- 折叠面板的互斥属性：`accordion: boolean`（源 A API 表）；源码实现 `getActiveKeys` 在 accordion 下截取单键（`es/Collapse/collapse.js:58-64`），点击已展开头会**收起**（`onItemClick` 先查 `index > -1` 再判断 accordion，`collapse.js:88-104`）→ 组件语义是「**至多一项**」而非「恒有一项」，§6.2 按此裁定。

### 3.2 与业界规范的结构性对照（源 C）

- **手风琴模式的互斥背书**：规范键盘条款明文覆盖互斥实现——「If the implementation allows only one panel to be expanded, and if another panel is expanded, collapses that panel」，并允许「恒有一项、不可收起」的变体（后者须 `aria-disabled` 标注）。用户意向「有且仅能开启一项」落在规范明确支持的实现区间内。
- **region 地标密度警告**：规范建议面板容器 `role="region"` + `aria-labelledby`，但「an accordion that contains more than approximately 6 panels that can be expanded at the same time」不宜使用（地标泛滥）——现状九面板**可同时展开**恰触发该警告；互斥改造后同开数恒 ≤1，结构上自动合规（现状 region 无名称的缺口不因此消失，仍登记 §8）。
- **选项卡模式的自动激活条件**：方向键移动焦点即切换面板（自动激活）只在「面板无显著延迟呈现」时推荐，否则应手动激活（焦点移动 + Enter/Space 确认）——本仓九面板内容重（表单 + 图表），若采标签页须用手动激活，进一步抬高交互成本。

## 4. 主题三：业界对「多区块长内容」的组织指导

### 4.1 渐进披露（源 F 第一篇，2006 年原文全文抓取）

- 定义与收益：「Progressive disclosure defers advanced or rarely used features to a secondary screen, making applications easier to learn and less error-prone」；首屏出现本身就是重要性信号（「The very fact that something appears on the initial display tells users that it's important」）；改善五项可用性指标中的三项——「learnability, efficiency of use, and error rate」。
- **对本项目的定位**：九面板整体就是「高级功能」层——它已经位于渐进披露的第二层（基础计算卡之后，App.tsx:310-312）。要解决的问题不是再加一层，而是**第二层内部的秩序**：九个入口同屏平铺、可全部展开 = 第二层内部无焦点。
- **复杂度无法压缩时的手段**：「chunk your advanced features into groups that make sense」——分组是推荐手段，但受层级上限约束（4.3）。
- **分步向导的边界**：「Staged disclosure (e.g., wizards) works only when steps have little interaction; it's problematic when steps are interdependent and users must alternate between them」——九面板虽不互依赖，但均为**高交互工具**（填参、运行、读图），且用户需要在工具间自由往返（如先贷款后收租），分步条强制线性寻址不成立。这是步骤条被排除的第二重依据（第一重为 §2 语义不符）。

### 4.2 移动端折叠面板（源 F 第二篇，全文抓取）

- 「on mobile, accordions are one of the most useful design elements」；「Accordions conserve space on mobile」，让用户「get the big picture before focusing on details」——九个收起头 ≈ 一屏内的迷你信息架构（mini-IA / in-page table of contents），与本项目「九头常驻、点谁开谁」的目标形态一致。
- 三条落地告诫，全部采纳为 §6 参数：① 展开时**不要把页面滚到别处**（防用户误判「换了新页面」而按返回离开）；② 长内容面板要有**持久的头部**（sticky header）以便不滚回顶部就能收起——本项目折叠头收起后仍在原位、无需额外实现，但 ④ 蒙特卡洛面板内容极长，其内部 sticky 运行条（global.css:982-998 修正）已在履行该职责；③ **第一项保持收起**以便扫读页面结构——对应本项目「默认全部收起」现状，互斥改造必须保留（见 6.2 决策点）。

### 4.3 信息架构分层与「同屏单一焦点」

- 层级上限（源 F）：「Designs going beyond 2 disclosure levels typically have poor usability because users get lost between levels; if 3+ levels seem needed, simplify instead」。现状层级 = 卡片（1）→ 面板（2），恰好两层。**若按「分块」指导把九面板分 3 组（估算类 / 风险对比类 / 原理类），层级变为卡片（1）→ 组头（2）→ 面板（3），踩中警告**→ 裁定不引入分组（完整裁定与备选见 §8.2）。
- 同屏单一焦点：九面板各自是完整工具（表单 + 输出 + 图表），两件工具同屏 = 两组表单字段争夺注意力，与设计规范既有的「同屏字段数上限」纪律（docs/research-responsive.md §10 工效行）同向。互斥展开把「同屏焦点数」钳制在 1，标签页同样钳制在 1——此维度两者同分，胜负由 §3 键盘与 §5 迁移成本决定。

## 6. 最终推荐方案与落地参数

### 6.1 主方案：互斥 Collapse + 标题两行文案

组件 API 用法（落地代码骨架，属性逐项注明依据）：

```tsx
// src/components/AdvancedPanel.tsx（改造示意）
import { Card, Collapse } from "@arco-design/web-react";

// 头部两行：header 接受 ReactNode（源 A API 表「折叠面板头部内容，允许自定义」）；
// 注意 header 渲染进 role="button" 头节点内部（源 B item.js:71），
// 内部只能放纯展示节点，严禁再放可交互元素。
function PanelHeader({ title, desc }: { title: string; desc: string }) {
  return (
    <div className="wf-collapse-head">
      <div className="wf-collapse-head-title">{title}</div>
      <div className="wf-collapse-head-desc">{desc}</div>
    </div>
  );
}

<Card title={t("advanced.cardTitle")} style={{ marginTop: 16 }}>
  <Collapse
    bordered={false}
    expandIconPosition="right"
    lazyload            // 保留：首展开才挂载、收起不卸载（源 B item.js:80），表单与运行结果不丢
    accordion           // 新增：互斥（源 A API 表；源 B collapse.js:94-95）
  >
    <Collapse.Item
      name="reverse"
      header={<PanelHeader title={t("advanced.reverseTitle")} desc={t("advanced.reverseDesc")} />}
    >
      <ReversePanel />
    </Collapse.Item>
    {/* 其余八项同构 */}
  </Collapse>
</Card>
```

- `lazyload` 与 `accordion` 可叠加：互斥只改 `onItemClick` 的键集合计算（collapse.js:88-104），不触碰 `Transition` 的挂载/卸载参数（item.js:80）——切换面板时旧面板收起、新面板展开，两者均已挂载（首次之后），无重复挂载开销。
- 现状 `expandIconPosition="right"`、`bordered={false}` 维持不变（视觉零迁移）。
- 基础模式「核心参数」折叠（`src/components/BasicCalculator.tsx:704-745`）为单条目折叠，**不**纳入本次互斥范围（无互斥可言，且改动面控制）。

### 6.2 决策点：「至多一项」vs「恒有一项」

- 用户反馈原话「有且仅能开启一项」存在两种实现解读：
  - **A 至多一项**（库语义原生）：点击已展开头可全部收起。源 B collapse.js:88-104：`index > -1` 分支先于 `accordion` 分支执行 → 已展开项再点即收起。
  - **B 恒有一项**（严格解读）：需受控 `activeKey` + 在 `onChange` 中拒绝空集合，且首屏必须默认展开一项。
- **裁定：采纳 A**。依据：① 与现状「默认全部收起」文案及行为衔接（首屏若强制展开一项，即违背源 F 4.2 第 ③ 条「首项保持收起以便扫读结构」）；② 源 C 手风琴模式将「允许收起」视为常规实现，「恒开」变体反而要求额外 `aria-disabled` 标注；③ A 是非受控一行属性，B 引入受控状态与存储联动，改动面大。登记为已决策项写入设计规范；「恒有一项」的受控写法存档如下备查：`activeKey={activeKey ?? "reverse"}` + `onChange={(k, keys) => keys.length && setActiveKey(keys)}`。
- 卡片标题文案随之改为互斥语义（§6.4），消除「按需展开」与实际行为的错位。

### 6.3 断点形态（与既有五档矩阵逐档衔接）

| 断点 | 形态 | 新增 CSS |
| --- | --- | --- |
| 375（紧凑） | 竖排堆叠九头（44px 档维持 global.css:884-889）；**仅显示短标签主行**，描述副行隐藏；展开面板单列（面板内既有 `useIsNarrowViewport` 逻辑不动，hooks.ts:72-96） | `.wf-collapse-head-desc { display: none }`（基态，移动优先） |
| 640（紧凑展开档） | 同 375；**起显示描述副行**（640 为 research-responsive §1.3 推导档） | `@media (min-width: 640px) { .wf-collapse-head-desc { display: block } }` |
| 768（唯一硬断点，组件库 md） | 竖排堆叠不变；展开面板内容区启用既有双列栅格逻辑（面板内 `column={{ xs: 1, md: N }}` 原样） | 无 |
| 1024 / 1440（桌面档） | 竖排堆叠不变（**不引入左右分栏**——见 §6.5 存档理由）；副行维持显示 | 无 |

- 五档零新增断点、零新增媒体查询方向（与 D1「CSS 一律 `min-width` 书写」一致，仅一处 640 起显示规则）；`prefers-reduced-motion` 清单（global.css:507-535）按类名继续命中，无需修改。
- 展开不滚屏（源 F 4.2 告诫 ①）：现状展开动画为高度过渡（源 B 折叠样式 `transition: height .2s`），浏览器锚定位置不变；落地验证时加查「展开九头中任意头，视口滚动位置不跳变」。

### 6.4 面板标题的导航文案规范

**结构规范**：主行 = 短标签（≤ 6 汉字 / ≈ ≤ 2 词），副行 = 一句话功能描述（≤ 18 汉字，12px 次要色 `--wf-text-xs` 口径）。三份语言文件键名不变、值拆分为 `*Title` / `*Desc` 双键（新增 9×2 键 + 移除原 9 个 `*Header` 键，见 §7.1 F2）。

**序号取舍裁定：移除圈号 ①–⑨**。依据：
1. 语义不符——序号暗示先后流程，而两套组件库均把「序号式流程」归给步骤条（§2 步骤条行）；九面板排序实为迭代历史（第 8、9 面板按规范文档追加，AdvancedPanel.tsx:3-5 注释自证），并非操作顺序。
2. 语言一致性——英语标题携带圈号属异形字符噪声（en.ts:122-136 实证），移除后三语结构对齐。
3. 副行承担「这是什么」的信息分层后，主行进一步缩短，圈号宽度在小屏头部占比更显冗余。
   备选（不采纳但登记）：若产品确需序号便于口头沟通（「打开第 4 个」），应以 `extra` 槽（源 A API 表）放弱化序号于头右侧，而非标题前缀。

### 6.5 补充方案（均非本轮实施）

1. **桌面标签页竖排增强（存档）**：若未来面板数增长（>12）或出现「两面板并排对照」的强需求，可在 ≥1024 档以 `Tabs type="card" tabPosition="left" overflow="dropdown" lazyload destroyOnHide={false}` 重构（`destroyOnHide=false` 保住表单状态，源 A API 表；`overflow="dropdown"` 兜住页签溢出）。**采纳前置条件（三条硬门）**：自补页签方向键导航 + 游移 `tabIndex`（对齐源 C，§3.1）；手动激活（Enter/Space 确认后切面板，源 C 自动激活条件不满足）；样式引入计入尺寸门禁（`main.tsx` 增 Tabs 样式行，scripts/check-size.mjs 预算复核）。本轮不做的理由：互斥 Collapse 以 1/5 的改动面拿到 32/35，标签页增量收益（同屏概览 4→5）不抵三条硬门成本。
2. **深链直达（候选）**：受控 `activeKey` 接收 URL 参数 → 打开分享链接时自动展开指定面板。前置：hash 前缀必须区别于分享载荷 `#s=`（share.ts:39），且写 hash 逻辑并入 share.ts 编解码纯函数对。登记为 P 后续候选，本轮不做。
3. **锚点 / 步骤条**：不采纳，理由见 §5；若未来恢复「多面板同开」形态且页面仍长，锚点（`hash={false}`）+ 侧栏 Affix 可作为寻路层回归，届时再评估。
