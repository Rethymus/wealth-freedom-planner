## §0 事件流出通用约定（七条算例共用裁定；实现须钉死，不得两算例两套口径）

1. **行号—年龄**：沿用 P8 §0.1——第 t 行行首年龄 = currentAge＋t−1；30 岁起算时行首年龄 = 30＋t−1。孩子年龄 = t − 出生行 t₀（出生行 0 岁）。
2. **事件流出统一口径（本清单核心裁定）**：一切事件金额按**基期名义**（「今天的钱」）理解，行内流出 = 金额×cumInfl_t（cumInfl_t = (1＋i_eff)^t，与生活费/储蓄**同一通胀因子同行取值**）。备选口径「事件年名义支付」被否决：制造两套钱、且与全部既有金额输入族（月开销、育儿 53.8 万 2024 价、医疗 2024 价，insights.ts 全表）不同口径。
3. **行归属**：事件流出计入该行 `withdrawal`（净额口径扩展：工作段不再恒 0）；`contribution` 不因事件调整（事件从资产池扣、不改储蓄基流——方向偏保守，与 480 附加项「提高备资」同向）。
4. **育儿**：出生行 t₀ → 成本行 [t₀, t₀＋17]（0–17 岁 18 行，报告口径 53.8 万对应 0–17 岁，insights.ts:149）；年成本 = costPerChild÷18（线性摊提，基期名义）；t₀＋17 ＞ horizon 时截断（窗口外成本不入账，口径明示）。
5. **医疗**：闭区间 [t₁, t₂] 每行附加 金额×cumInfl_t；区间外零影响；`phase` 字段仅标记、金额独立（多阶段并列合法）。
6. **购房**：事件行一次性支付 = 房价×cumInfl_Y；贷款分期不在本轮（`loan` 维持类型承载，p8-spec.md:63 同口径）。
7. **重叠裁定（⑥ 的裁定登记）**：同一年多事件流出**线性叠加**（相加进 withdrawal；无交互项、无上限、无次序依赖）。加法交换 ⇒ 行值对登记顺序不变（⑥ 实测三序全精度逐字节相等）；总差分 = 各事件单独差分之和（叠加原理，⑥ 数值验证）。耗尽判定（全精度 closing ≤ 0）在叠加后净行上照常执行。
8. **事件族 × 一次性附加族**：事件流出进时间线行；`base.majorInvestment / healthReserve / childCount×costPerChild` 进临界值/备资参考线（pension.rs:290-303 R5 归属不动）。引擎**不跨族自动去重**——同一事项两处登记即双计，须口径注明示（与 P8 §1.4「两族分水岭」同款处置）。
9. **事件不改目标族与养老金**：targetValue 仍生活费口径（育儿不进月开销——R5「附加项与生活费分列」的时间化延伸）；pensionMonthly / bridgeYears 与事件无关。首达年单调性：流出 ≥ 0 ⇒ 有事件路径 closing 逐行 ≤ 基线 ⇒ fiFirstYear 只能推迟或不变（⑥ 显示可推到 horizon 外 = −1）。
10. **购买力底线判定（⑤ 的裁定登记）**：达标 ⟺ closing_t ≥ targetValue×cumInfl_t ⟺ closing_t÷cumInfl_t ≥ targetValue（实口径底线）。cumInfl_t ≥ 0.99^t ＞ 0（i_eff 钳 −0.99，finance.ts:543/:747 防御同源）——实口径换算**无除零路径**；i = 0 ⇒ 实 = 名。禁用「名义资产 ≥ 基期名义目标」错觉判定（⑤ 行 13 反例）。

## §6 算例⑥：多事件重叠年叠加语义（口径裁定登记）

**输入**：ACCUMULATION_DEFAULTS 但 `currentAssets: 1,000,000`（同 §1 理由）；**三事件同年窗交叠**：`childBirth { year: 3 }`（成本行 3–20，年 30,000 基期）＋ `homePurchase { year: 5, amount: 1,200,000 }` ＋ `healthPhase { s: 10, e: 15 }`（年 30,000 基期）。**裁定**：§0.7 线性叠加——withdrawal_t = 净生活费 ＋ Σ 事件流出_t；行值对登记顺序不变；总差分 = 各事件差分之和。

**手算（重叠行流出闭式）**：同因子可合并——行 5 = (30,000＋1,200,000)×1.02⁵ = 1,230,000×1.1040808032 = **1,358,019.39**；行 10–15 = (30,000＋30,000)×1.02^t = **60,000×1.02^t**（行 10 = 73,139.67、行 15 = 80,752.10）；行 3 = 31,836.24、行 16–20 = 30,000×1.02^t（行 16 = 41,183.57）、行 21+ = 0。

## §8 边界结论（四条）

1. **事件流出必须与行通胀因子同源**：所有事件金额按基期名义×cumInfl_t 落位（§0.2）——①的 1,324,896.96 ≠ 1,200,000、②③⑥的重叠行合并闭式（65,880/95,880×1.02^t 族）都依赖单因子口径；双通胀族（教育/医疗专项通胀）登记为已知简化，不进本轮。
2. **叠加 = 线性，是唯一可裁定的语义**：⑥ 实证三序逐字节相等 ＋ 差分叠加（Δ总 = ΣΔ单）——事件族不引入交互项/上限/次序，是加法交换律的结构性结论，任何「事件优先级」设计都会破坏它；耗尽与 FI 判定在叠加净行上照常执行，不因事件特判。
3. **事件族 × 一次性族的双计风险只能靠口径注解决**：⑦用「一次性预留含在期初资产」的 P8 口径避开双计；引擎不去重（§0.8），UI 须在同屏明示两族并存的口径——与 P8「两族分水岭」同款处置延伸。
4. **事件把「首达年」从指标变成视界量**：①推迟 16 行、②推 6 行、③推 2 行、⑥推到 −1——fiFirstYear 对事件流出的敏感度是事件编辑器的核心展示面；同时⑤钉死判定本身（实口径底线）不受任何事件影响。
