# 响应式设计专项研究（research-responsive）

> 版本：v1.0（2026-11-19）
> 范围：本应用「财富自由规划工具」全部界面（顶栏 / 基础计算 / 高级面板 / 图表 / 表格）。
> 核心立场：**响应式不是把桌面页缩放塞进小屏，而是在每个断点上依据人体工程学与用户心理学重新设计**——同一份信息在不同断点上以不同的「问题」呈现。
> 门禁声明：本文引用的官方规范一律以中性来源标签（源 A–G）标注「哪一类规范的哪一节」，不出现平台/公司/产品品牌名；抓取时间均为 2026-11-18/19。原始 URL 因门禁「全程中性表达」未收录，抓取过程与来源对应关系见 §13。

## 0. 摘要

1. **断点体系**：端侧系统官方「窗口尺寸类」数值（compact < 600 / medium 600–840 / expanded 840–1200 / large 1200–1600 / extra-large ≥ 1600，源 B）与两条 Web 组件库栅格断点带（源 C：xs<576 / sm≥576 / md≥768 / lg≥992 / xl≥1200 / xxl≥1600 / xxxl≥2000；源 D：sm 768 / md 992 / lg ≥1200 三档）交叉对照后，本项目采用 **375 / 640 / 768 / 1024 / 1440** 五档；768 与组件库 md 完全对齐（现状代码已按 768 对齐），640 为推导档（§1.3、§12）。
2. **顶栏工具组**：按「宽度预算」逐档给出收纳规则——375 两行堆叠 + 标签全隐藏、640 单行收纳态、≥768 单行完整态 + sticky（现状已具备，补 375/640 档细则，§2）。
3. **触控目标**：≥44px 已覆盖按钮/输入框/顶栏下拉/开关（global.css:399-420、422-436）；三处缺口（预设按钮 32px、场景标签内 mini 按钮、折叠头无最小高）列入采纳清单（§5）。
4. **工效**：单手握持占比 49%（36% 托举 / 15% 双手，源 F）；拇指热区按视口高度百分比给出系数带（自然可达 [0.66H, 1.0H] / 伸展区 [0.33H, 0.66H) / 困难区 [0, 0.33H)），主要动作（复制分享 / 运行模拟）在 <768 档落底部吸附操作条（§7）。
5. **心理学**：渐进式披露（源 G）已有三处落地（核心参数折叠 / 8 个高级面板默认收起 / 敏感性默认折叠）；补「同屏可见字段数上限」（≤768 档 4 个 / 768–1024 档 8 个 / ≥1024 档 10 个）、决策顺序一致性规范与选择数量约束（≤5 个同时呈现的独立选项，§8）。
6. **矩阵**：§10 给出 5 断点 × 10 主题行的断点决策矩阵表（含工效与心理学 4 行：拇指热区覆盖判定 / 同屏字段数上限 / 决策顺序一致性 / 移动端输出卡紧凑模式）。§11 为逐条设计采纳清单。

## 1. 主题一：断点体系（官方数值交叉对照与本项目映射）

### 1.1 端侧系统官方数值

**源 B「窗口尺寸类（Window size classes）」一节**（材料类系统设计语言 / 端侧系统开发者适配文档，2026-11 抓取，数值一致）：

| 类别 | 宽度区间 | 高度区间 |
| --- | --- | --- |
| compact | 宽 < 600dp | 高 < 480dp |
| medium | 600dp ≤ 宽 < 840dp | 480dp ≤ 高 < 900dp |
| expanded | 840dp ≤ 宽 < 1200dp | 高 ≥ 900dp |
| large | 1200dp ≤ 宽 < 1600dp | — |
| extra-large | 宽 ≥ 1600dp | — |

（注：dp 为密度无关像素；CSS px 与 dp 在标准密度下 1:1。）

**源 A「Layout · Size classes」一节**（端侧系统人机界面指南）：水平/垂直空间各分 **compact / regular 两态**，**不给像素分界值**；关键规范三条：
- 「按尺寸类而非设备类型或方向决定布局」；
- 「尺寸类变化时**功能保持不变**，可变化的是同屏可见的功能数量」——顶栏收纳的官方依据；
- 「按相对重要性排序内容……把最重要的项放在顶部」——移动优先内容排序的官方依据。

### 1.2 Web 组件库栅格断点带

**源 C（本应用所用组件库）**：官方实现响应式观察器（本仓依赖目录内 `<组件库包名>/es/_util/responsiveObserve.js:14-22`，本会话直接读取，断点映射逐字转录如下）：

```
xs: (max-width: 575px)   sm: (min-width: 576px)   md: (min-width: 768px)
lg: (min-width: 992px)   xl: (min-width: 1200px)  xxl: (min-width: 1600px)
xxxl: (min-width: 2000px)
```

文件头注明该实现源自另一通用组件库——即两条组件库断点带同源，可互为交叉印证。

**源 D「布局规范 · 断点系统」一节**（同类通用组件库设计规范页，2026-11 抓取）：
- 共 **3 个断点**：sm = **768px**（768–991，平板）、md = **992px**（992–1199，小屏电脑）、lg ≥ **1200px**（大屏电脑）；
- 栅格组成：网格基数 **8px**、槽宽 **16px**、安全边距 **24px**（建议 8 的倍数）、内容区 **12 栅格**；
- 侧边导航在浏览器宽度 **< 992px** 时自动从展开态变收起态（「按断点收纳功能」的组件库实践）；
- 标准画板宽 1440px / 1920px。

**源 B「响应式布局网格（Responsive layout grid）」一节**：列数随断点变化（360dp 手机 4 列 / 600dp 平板 8 列），列宽用百分比、槽宽按断点固定（手机 16dp / 平板 24dp）、边距手机 16dp。

### 1.3 本项目断点映射（375 / 640 / 768 / 1024 / 1440）

| 项目档位 | 对应官方区间 | 选择理由 |
| --- | --- | --- |
| **375**（紧凑基线档） | compact（<600dp）| 最小设计基线；现状无溢出的验收口径 |
| **640**（大手机/小平板竖屏档）| compact 上沿 → medium 下沿（600–840 之间的过渡带）| 顶栏宽度预算的收纳临界点（§2.2 推导）；600dp 窗口类的近邻整档 |
| **768**（双列起档）| 组件库 C md（≥768）＝源 D sm（768）| **与组件库 md 完全对齐**——现状 sticky、工具组换行、Descriptions 纵横切换、`useIsNarrowViewport` 全部锚定 767.9/768（global.css:162,191,555,716；hooks.ts:74-75），改动成本最低 |
| **1024**（桌面双列完整档）| 源 D md 档（992–1199）的整档化；expanded（840–1200）内 | Descriptions 3 列完整呈现的起点；高级面板**维持单列**（未显式传 md=12，裁定见 design-spec §3.6 与 p3-spec §12 #18——记述修正，原文「高级面板两列」与实现不符） |
| **1440**（宽屏封顶档）| large（1200–1600）内；源 D 标准画板宽 1440 | 内容封顶 maxWidth 1112 居中（App.tsx:240），超越此档不再增长 |

规则：**768 是唯一硬断点**（承载组件库 md 语义）；375/640 是紧凑端两档「重设计」档；1024/1440 是桌面两档「展开」档。CSS 一律 `min-width` 书写（移动优先），与组件库实现方向一致。

## 2. 主题二：顶栏工具组收纳策略

### 2.1 现状

- 顶栏含 5 个控件：币种 Select（width 150）、色盲开关（`wf-touch-target-sm` 命中 44px）、语言 Select（width 130）、主题圆形按钮（28×28 本体 + 20px 扩展 = 48px 命中）、外加 3 个文字标签（App.tsx:186-230）。
- 布局：`wf-header` 允许换行（global.css:540-544）；`<767.9px` 工具组内部换行（global.css:555-560）；`<640px` 内边距 24→16px（global.css:578-582）；≥768 sticky + 最小高 56px（global.css:162-173）。
- 组件库 Select 已可收缩（global.css:572-576）。

### 2.2 宽度预算推导（决定收纳档位）

品牌区 ≈ 图标 20 + 间距 8 + 标题（16px × ~8 字）≈ **156px**；
工具组（有标签）≈ 标签 40+52+40 + Select 150+130 + 开关 18 + 圆钮 28 + 间隙 60 ≈ **518px**；
合计 ≈ **674px** + 两端内边距 48px（≥768 档）。

- **≥768**：可用 720px ≥ 674px → 单行完整态（标签全保留），与现状一致。
- **640–767**：可用 608px < 674px → **收纳态**：隐藏「色盲友好」文字标签（开关状态语义由 aria-label/title 与开关形态承载，符合源 A「功能不变、可见数量可变」），两个 Select 缩至 110 / 96px → 合计 ≈ 544px ✓。
- **375–639**：可用 343px 连收纳态单行都放不下 → **两行堆叠**：第一行品牌（标题字号降级 16→14px），第二行工具组（**三个文字标签全部隐藏**、Select 窄档 104 / 88px、行内右对齐），换行机制复用现状 `flex-wrap`（global.css:540-544）。

隐藏标签必须保留无障碍等价物：`aria-label`（主题按钮已具备，App.tsx:218）；两个 Select 增加 `aria-label`；色盲开关增加 `aria-label`（采纳清单 D2）。

### 2.3 收纳手段的优先级（源 A「size classes 变化时功能不变」推导）

1. **换行**（最低成本，≥640 恒可用）→ 2. **标签隐藏**（配 aria-label 等价）→ 3. **控件收缩**（Select 窄档显示币种符号而非「代码（符号）」全称）→ 4. **图标化**（语言切换可降为「中/繁/EN」缩写）→ 5. **抽屉/溢出菜单**（本应用控件 ≤5 个，**不采用**——抽屉会为省 100px 引入一整层新交互，违反渐进式披露的层级上限原则，§8.1）。

## 3. 主题三：表单与面板

### 3.1 两列栅格切点

- 现状：字段组件 `Col xs={24} md={md}`（fields.tsx:79，默认 24 单列），高级面板**未显式传 `md`（维持默认 24 单列）**——本节原文「高级面板显式 md={12} 两列」为记述错误，1024 实测高级面板字段单列纵排（验收 S3-4），维持单列裁定见 design-spec §3.6 与 p3-spec §12 #18；`FieldRow` gutter `[16, 0]`（fields.tsx:143-149）。
- 规范依据：源 C md=768 与源 D sm=768 双源一致 → **两列切点维持 768，不改**。
- 补强：<640 档关闭 FieldRow 的水平 gutter（`gutter={[0, 0]}` 或 CSS 化），行距交给字段自身 `margin-bottom: 10px`（global.css:640-642），避免 375 下两列残留 16px 侧向空白压缩输入框；标签换行机制已具备（global.css:645-650）。

### 3.2 Descriptions 纵横切换

- 现状：`layout={isNarrow ? "vertical" : "horizontal"}`、`column={{ xs: 1, md: 3 }}`（LoanPanel.tsx:130-136；MonteCarloPanel.tsx:703-708；PensionPanel.tsx:161-166,188-193 用 md:2）；窄屏判定 `useIsNarrowViewport()`（hooks.ts:70-96，媒体串 `(max-width: 767.9px)`）；窄屏 label 换行兜底（global.css:716-720）。
- 规范依据：源 A「按尺寸类决定布局」；源 D「断点上布局切换」。现状已双源合规，**维持 767.9 切点**。
- 375 档追加：vertical 模式下值右对齐 + 等宽数字（`font-variant-numeric: tabular-nums`，全局已挂 `.wf-amortize-table/.wf-realtime`，扩展到 Descriptions 值单元格），扫读时数值列形成视觉右边缘。

### 3.3 Collapse 展开密度

- 现状：核心参数折叠（BasicCalculator.tsx:653-694）+ 8 个高级面板默认收起 + `lazyload`（AdvancedPanel.tsx:24）+ 敏感性默认折叠（BasicCalculator.tsx:393）——三层折叠全部符合源 G 渐进式披露（§8.1）。
- 规范依据：源 G「超过 2 层披露通常可用性低」——本应用最深披露链为「基础表单 → 核心参数折叠」与「基础表单 → 高级面板 → 子面板内折叠」，均为 **2 层**，合规上限。
- <768 档密度细则：折叠头补最小高 44px（触控目标，§5）；折叠头文案在紧凑档追加默认值提示（如「回报假设（默认 6% / 2%）」），让用户不展开也能校准预期——降低展开决策成本（§8.2）。

### 4.2 规范依据与小屏规则

官方规范无图表高度硬性条款（源 B 响应式网格只管布局骨架）；以下规则以 **源 A（内容按重要性排序）+ 源 F（小屏拇指滚动单手姿态，图表下方不留交互）+ WCAG 2.2 §1.4.10 重排（宽 320 CSS px 内容可重排）** 为锚，具体数值为项目推导（§12 偏离 #4）：

1. **高度三档**：`<640`：统一 240px（320→240、280→240、龙卷风 240 不变）；`640–767`：280px；`≥768`：320px（现状）。三档均 ≥ 220px，保证 5 条刻度 + 图题的最小可读高度。
2. **轴刻度密度**：小屏 X 轴刻度 **≤5 个**（图表库 `interval` 或刻度过滤），Y 轴宽度 72→56px、刻度字号保持 12（再小会跌破 12px 可读下限，与 `--wf-text-xs` 一致）；龙卷风图类目标签宽 56px 维持。
3. **图例换行**：<640 图例一律纵排（现状龙卷风图例已纵排两行，BasicCalculator.tsx:229-238；多路径折线图例在紧凑档隐藏、由 aria-label + 数值表替代——现状「数值表替代图例」口径已在 MC 面板实现，MonteCarloPanel.tsx:703 注释）。
4. **图表交互**：小屏图表不承载点击交互（拇指滚动姿态下 tooltip 不可达），信息必须可从图下数值行获得——现状敏感性图已满足（图 + 数值行并存）。

## 5. 主题五：触控目标 ≥44px 适用清单

规范依据：**源 A「Accessibility · Offer sufficiently sized controls」**：默认控件尺寸 **44×44pt**、最小 28×28pt，带边框元素四周留 **12pt**、无边框留 **24pt** 间距；**源 B「Accessibility · Touch targets」**：触控目标 ≥ **48×48dp**（≈9mm），目标可超出视觉边界，推荐触屏目标 7–10mm、指针目标 ≥44×44dp；**WCAG 2.2 §2.5.5（增强档）** ≥ **44×44 CSS px**、**§2.5.8（最低档）** ≥ 24×24 CSS px 或 24px 间距圈不相交。本项目取 **44px 命中区**（源 A 默认值 = WCAG 增强档）。

### 5.1 已达标（本会话核对）

| 控件 | 机制 | 位置 |
| --- | --- | --- |
| 全部按钮 | `pointer: coarse` 或 <767.9 下 `min-height: 44px` | global.css:399-403 |
| 圆形图标按钮（主题切换） | 28×28 本体豁免 + 触控区扩展 20px = 48px | global.css:405-411；App.tsx:213 |
| 数值输入框 | `min-height: 44px`（触屏/窄屏） | global.css:413-415 |
| 顶栏下拉 | `min-height: 44px` | global.css:417-419 |
| 开关（孩子决策 / 色盲） | 触控区扩展包装（24+20=44 / 16+28=44） | global.css:422-436；App.tsx:197；BasicCalculator.tsx:593 |

### 5.2 缺口（采纳清单依据）

1. **预设画像按钮**：`min-height: 32px`（global.css:754）→ <768 应为 44px。
2. **场景对比面板标签内的 mini 文字按钮**（载入/删除，`size="mini"` ≈ 24px 命中）（ScenarioPanel.tsx:204-208）→ 补触控区扩展包装。
3. **折叠面板头**：无显式最小高（global.css:389-397 只有按压反馈）→ 触屏/窄屏补 `min-height: 44px`。
4. **字段提示图标**（hover 型 tooltip）：触屏上 hover 不存在——提示文案已有 `hint` 兜底通道（fields.tsx:101-110），<768 档点击图标应改为触发展开式提示或聚焦输入框时展示（低优先级）。

### 5.3 间距

控件相邻间距 ≥8px（8pt 网格既有令牌）满足 WCAG §2.5.8 的间距豁免口径；折叠头整行可点，天然超宽。

## 6. 主题六：表格横向滚动容器规范

规范依据：**WCAG 2.2 §1.4.10「重排（Reflow）」**：内容须可在 **320 CSS px 宽**（400% 缩放等效）内重排为单列、无双向滚动；**数据表格作为需要二维布局的例外可双向滚动，但表格内的单元格不豁免**（单元格内容不得逐字符断行）。

现状（global.css:700-710）：摊销表容器 `overflow-x: auto` + 表格 `min-width: 560px`，桌面 ≥560px 时 `width: 100%` 无滚动——已符合「例外内允许表格级横滚」；期次列 96px 禁换行（LoanPanel.tsx:50-56）解决单元格断词。场景对比表包 `overflowX: auto`（ScenarioPanel.tsx:229-238），指标列固定 150px（ScenarioPanel.tsx:147），≤12 情景列。

<768 档容器细则（采纳清单 D7）：
1. **首列（期次/指标）sticky left**：横向滑动时行标识恒可见——解决「滑走后不知道在看哪一期」的定位丢失；
2. **容器右缘渐隐遮罩（宽 24px）**：暗示「右侧还有内容」，替代抽象滚动条（触屏无滚动条视觉）；
3. **滑动提示**：表格上方一行 12px 副注「左右滑动查看全部列」（现状已有行数注记 `wf-panel-note` 可承载）；
4. 列宽纪律：数值列 `wf-nowrap` + 等宽数字（现状已挂），**禁止**在 <768 为塞下全表而压缩列宽（宁可横滚，不可断字）。

## 7. 主题七：人体工程学（拇指热区与动作落位）

### 7.1 握持与可达性依据

**源 F（移动设备握持方式实地观察研究，2013）**：触屏用户中**单手 49%、托举（一手持机一手拇指）36%、双手 15%**；研究者绘制的可达图分三色区：**绿 = 容易触及、黄 = 需伸展、红 = 需变换握持方式**；且用户会**随任务切换握持**（例如为够到顶部而调整握位）、竖屏姿态占绝对主导。（研究者明示三区为近似区间，未给出统一百分比。）

结合源 A 默认控件 44pt 的手指物理尺寸（≈9–10mm 指腹），本项目按视口高度百分比给出发力系数带（**项目推导值，见 §12 偏离 #2**）：

| 区带 | 视口高度系数 | 375×667 实例 | 430×932 实例 | 姿态含义 |
| --- | --- | --- | --- | --- |
| 自然可达区 | y ∈ [0.66H, 1.0H] | y ≥ 440px | y ≥ 615px | 拇指自然弧线内，可盲操作 |
| 伸展区 | y ∈ [0.33H, 0.66H) | 220–440px | 307–615px | 可达但需注意力+微调，点按精度下降 |
| 困难区 | y ∈ [0, 0.33H) | y < 220px | y < 307px | 需变换握持（源 F 红区语义），只放「查看」不放「操作」 |

### 7.2 主要动作落位规则

| 动作 | 频率 | 现状落位 | 判定 | 规则 |
| --- | --- | --- | --- | --- |
| 复制分享 | 高（每次调整参数后） | 输入卡末尾（BasicCalculator.tsx:698-713） | ✓ 滚动到末尾即落自然可达区 | <768 档升级为**底部吸附操作条**（sticky bottom），常驻自然区 |
| 运行模拟（MC/打工） | 中 | 面板中部按钮行（MonteCarloPanel `wf-mc-actions`） | △ 展开后位于伸展区 | <768 档运行按钮随面板内容尾部对齐 + 底部吸附条收纳主运行动作 |
| 展开面板/折叠 | 高 | 折叠头整行 | ✓ 整行宽命中 | 折叠头 44px 最小高（§5.2） |
| 敏感性展开 | 中 | 输出卡内 text 按钮 | △ 输出卡置顶 = 困难区 | 可接受：输出卡是「查看」区，展开属低危操作；<768 档吸附态下按钮随卡吸附于顶部，此时用户处于「阅读姿态」（源 F：用户会按任务换握持） |
| 顶栏工具（币种/语言/主题） | 低 | 顶栏 = 困难区 | ✓ 可接受 | 低频设置类操作不强制热区（源 A：顶部放重要但非高频内容） |

### 7.3 长表单滚动中的姿态切换

- **滚动 = 拇指、点按 = 换姿态**：字段纵向排列保证「一路滚到底、逐屏填 2–4 个字段」；滚动条动作留给拇指，输入动作集中在自然可达区窗口内完成（填完一屏的字段 → 滚动 → 再填）。
- 同屏可见字段数上限（§8.2）正是姿态切换成本的控制器：字段过多会迫使「滚动定位 → 举手点按」高频交替。
- 输出卡 sticky 置顶（现状）承担「随时回看结论」职责——查看属于困难区可容忍操作；**任何写操作（输入/按钮）不得常驻困难区**。

## 8. 主题八：用户心理学

### 8.1 渐进式披露适用清单

规范依据：**源 G「渐进式披露」**：把高级/低频功能推迟到二级界面；超过 2 层披露通常可用性低；高级入口必须显眼。

| 内容 | 默认状态 | 展开后是否保留 | 理由 |
| --- | --- | --- | --- |
| 核心参数（回报率/通胀） | 折叠（BasicCalculator.tsx:653） | 保留展开态直至离开页面 | 中频校准项，多数用户吃默认值 |
| 8 个高级面板 | 全部收起 + lazyload（AdvancedPanel.tsx:24） | 各自独立保留 | 源 G「多个二级入口，各由不同控件唤起」的合规形态 |
| 欲望敏感性 | 折叠（BasicCalculator.tsx:393） | 保留；重挂载不复活 | 输出解读型内容，按需展开 |
| 摊销表明细 12 行 | 部分展示（slice(0,12)，LoanPanel.tsx:151） | 注记「共 N 期」 | 数值验证型内容，前 12 行覆盖绝大多数排查需求 |
| 输出卡明细拆解 | 展开 | —— | **不披露**：核心结论（§9.2） |
| 预设画像按钮 | 展开 | —— | **不披露**：首屏决策入口 |

规则：**默认收起的都是「参数」或「证据」；默认展开的只有「结论」和「决策入口」**。展开状态保留在会话内不自动收回（避免「我刚才展开了什么」的回忆负担，源 G 短期记忆约 7 组块、20 秒衰减）。

### 8.2 认知负荷控制

规范依据：**源 G「最小化认知负荷」与「短期记忆与网页可用性」**：工作记忆约 7 组块且 ~20 秒衰减；应最小化 extraneous（外在）负荷；组块化与识别优于回忆。

1. **同屏可见输入字段数上限**（项目推导值）：`<768`：**4 个/屏**；`768–1024`：**8 个/屏**；`≥1024`：**10 个/屏**。现状 375 首屏在输出卡置顶后自然可见 ~3 个字段（月开销 / 孩子开关 / 健康预留）——合规；各高级面板字段总数（11–21 个）全靠折叠分屏，展开后单屏仍受同上限约束（超过时靠滚动分段，不在展开态一次铺满）。
2. **分组标签可扫读性**：分组头（卡片标题 / 折叠头 / `wf-realtime` 底色区）承担组块边界；`wf-realtime` 着色底（global.css:672-683）就是「这块是回显不是输入」的视觉锚。新规则：<768 档分组头与首字段间距 ≥12px、组与组之间 ≥24px（`--wf-space-5`），维持组块感。
3. **提示收敛**：字段提示已有两级（tooltip 图标 + hint 文案，fields.tsx:82-110）；小屏 hint 优先（§5.2 缺口 4），tooltip 图标在触屏退化为补充入口。

### 8.3 决策顺序与字段顺序一致性

自然决策流：**先「每月花多少」→ 再「孩子决策」（开关 + 条件字段）→ 再「预留」（健康 / 大额）→ 最后「回报假设」（折叠）**。
现状字段顺序完全一致（BasicCalculator.tsx:575-651：monthlyExpense → planChildren → childCount/cost → healthReserve → majorInvestment → currentAssets → 折叠回报假设）→ **锁定为规范，任何断点不得重排语义顺序**：
- 375/640：顺序 = 纵向滚动顺序；
- ≥768：顺序 = 组内「左→右、上→下」（md=12 双列时孩子两字段并排，组内顺序不变）；
- 「已有资产」（选填追踪项）插在预留与回报假设之间属于决策流尾部，标记「选填」弱化即可，不前移（前移会打断「花销→家庭→预留」的心理链条）。

### 8.4 选择数量约束

同屏一次呈现的**独立选项 ≤5**（依据：源 G 短期记忆组块 + 识别优于回忆；数值为项目上限）：
- 预设画像 4 按钮 + 1 个「自定义」徽标 = 5 ✓（BasicCalculator.tsx:534-554）
- MC 收益模式 2 选 ✓、支取策略 3 选 ✓（MonteCarloPanel.tsx:315-323, 344-353）
- 语言 3 选、币种下拉（展开型，屏显 1 项）✓
- 若未来新增选项组超过 5 个，先合并语义，再考虑二级披露；**禁止**引入第 3 层披露（源 G 上限）。

## 9. 主题九：多思维框架

### 9.1 移动优先的内容优先级

规范依据：源 A「按相对重要性排序内容，最重要的放顶部」+ 源 G 移动端「推迟次要内容」。

| 优先级 | 内容 | 现状承载 |
| --- | --- | --- |
| P0 结论 | 临界值大数字 + 进度环 | 输出卡置顶 sticky（BasicCalculator.tsx:436-529）|
| P1 决策输入 | 决策流 4 组字段 | 输出卡下方，顺序锁定（§8.3）|
| P2 过程证据 | 敏感性 / 图表 / 表格 | 折叠 + 面板 |
| P3 说明 | 规则来源、免责声明 | 次要文案 + 页脚 |

小屏上**结论优先于过程、数值优先于说明**：输出卡里大数字（32px）在说明文字之前；明细拆解（`wf-output-breakdown`）排在两条 summary 行之后（现状顺序正确）；<768 档明细拆解可压缩为单行摘要 + 展开（采纳清单 D9）。

### 9.2 「每屏一个核心问题」

| 断点 | 首屏唯一核心问题 |
| --- | --- |
| **375** | 「**我每个月花多少钱，就能多久接近自由？**」——即「月开销 → 临界值」的一问一答；其余一切（孩子、预留、回报）都是这一问的修正项 |
| 640 | 同 375（答案与修正项同屏开始出现）|
| 768 | 「我的生活方式决定目标，我的回报假设决定路径」——问题拆为左右两个组块 |
| 1024+ | 「多情景下我的目标与路径长什么样」——问题升级为对比与稳健性 |

映射纪律：375 首屏**只允许一个数值焦点**（大数字），进度环是其辅助刻度；768 起才出现第二数值焦点（`wf-realtime` 实时回显区可与输出卡并存于首屏）。

## 12. 偏离与推导说明（deviations）

1. **640 档为项目自定义**：源 C 两档间为 576，源 D 起点为 768，均无 640；640 依据 600dp 窗口类档位与 §2.2 宽度预算推导。若要求与组件库断点严格对齐，可将 640 改为 576（改动面：D2/D3/D5/D7/D9 五条），语义不变。
2. **拇指热区系数带（0.33H / 0.66H）为项目推导值**：源 F 只给出绿/黄/红三区语义与握持占比，无统一百分比；经典「四区图」原始页面已 404 且无存档，未采用。实施前建议以 375×667 与 430×932 两档真机做可达性自测校准。
3. **同屏字段数上限（4/8/10）与选项数上限（5）为项目目标值**：依据源 G 认知负荷与短期记忆研究推导，官方无硬性数值。
4. **图表高度三档（240/280/320）为项目推导**：官方规范无图表高度条款；仅以重排（宽 320 CSS px）与刻度可读性（12px 下限）间接锚定。
5. **源 A 尺寸类为定性二态（compact/regular），无像素分界**：375 映射 compact 依据其描述性定义；像素级数值全部来自源 B 窗口尺寸类与源 C/D 栅格带。
6. **两次抓取失败未采用的佐证**：材料类系统「底部导航」组件页（SPA 未渲染）与「拇指四区」图（404）；相关结论改以源 F 三区语义 + 现状代码核对承载。
